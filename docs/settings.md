# 設定ファイルの場所

`appsettings.json`（登録フォルダ）と `lang.json`（言語設定）は、`AppContext.BaseDirectory` を基準とした絶対パスで読み書きする。スタートアップやショートカットからの起動でも同じファイルを使用する。

ZIP展開型の配置と既存設定を維持するため、保存先は実行ファイルと同じフォルダとする。アプリはユーザーが書き込み可能なフォルダに配置する。フォルダ登録・削除時に即時保存する。保存に成功してから購読中のUIへ通知し、失敗した場合は警告を表示して変更前の登録内容を維持する。終了時の書き戻しは行わない。

旧版で別の作業ディレクトリに作成された設定は自動探索しない。引き継ぐ場合はアプリを終了し、必要な設定ファイルを実行ファイルと同じフォルダにコピーする。

## 保存と読み込みの失敗

同じディレクトリの一時ファイルへJSONを書き込み、ディスクへのフラッシュ後に既存ファイルを置換する。新規作成時は上書きしない移動を使用する。失敗時は一時ファイルの清掃を試み、元のエラーを通知する。設定ファイルが存在しない場合だけ初期値を使用し、JSON破損・必須項目欠落・アクセス拒否は起動を中止して元ファイルを残す。

`lang.json` は初回のみ雛形を作成する。作成できなければ警告して既定の表示を使用する。既存ファイルは終了時に上書きしない。

この方式は完全な停電耐性や複数プロセス間の変更統合を保証しない。複数起動して変更した場合は最後に成功した保存が残る。

## 自動テスト

`dotnet run --project tests/Settings.Tests.csproj -c Release`

アプリ本体の保存処理を直接使い、終了せずに再読み込みできること、登録と削除、作業ディレクトリ変更、破損設定の保護、保存失敗時の画面状態維持、一時ファイル清掃を確認する。Windows CIではファイルロック時の置換失敗と既存データの維持も確認する。

## Windowsでの確認

1. アプリでフォルダを登録する。終了操作をせずに保存されることを確認する。
2. 実行ファイルと同じフォルダに `appsettings.json` が保存されたことを確認し、タスクマネージャーで終了する。
3. 別の書き込み可能なフォルダを「作業フォルダー」に指定したショートカットで起動し、登録フォルダが表示されることを確認する。
4. アプリを終了し、作業フォルダに設定ファイルが作成されていないことを確認する。
5. スタートアップに登録したショートカットからログイン時に起動し、同じ登録フォルダが表示されることを確認する。

6. フォルダを削除した直後にも強制終了し、再起動後に削除が維持されることを確認する。
7. 保存先への書き込みが拒否される状態で登録・削除し、警告が表示され、表示上の登録内容が変わらないことを確認する。
